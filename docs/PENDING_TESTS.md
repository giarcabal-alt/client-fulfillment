## 2. ATS Step 3 — Resume extraction + normalization (existing candidate)

**A real bug was found and fixed before this section could run at all**, not just a code-level issue caught by review: the very first "Parse resume" attempt failed with `Couldn't parse this resume. Please try again.` Dev server logs showed the actual cause: `Failed to parse resume: Error: Setting up fake worker failed: "Cannot find module '.../pdf.worker.mjs'..."` — under Turbopack's dev SSR bundling, `pdf-parse` (via `pdfjs-dist`)'s default relative worker-module resolution breaks because the sibling `pdf.worker.mjs` isn't copied into the chunk output. Fixed in `src/lib/talent-acquisition/resume-text-extract.ts` by explicitly pointing `PDFParse.setWorker()` at an absolute `file://` URL resolved via Node's own `path`/`url` modules (not a static import Turbopack would try to bundle) — this sidesteps the broken lookup. Required a full dev-server restart to take effect (pdfjs-dist caches its fake-worker setup in a `shadow()`-memoized getter on first access, so a mid-session HMR reload wasn't enough once the first failed attempt had poisoned that cache). **This is a genuine production-relevant bug** — it would affect any real PDF resume upload, not just this test — and is now fixed, not just worked around for the test.
